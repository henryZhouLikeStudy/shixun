# AI 缓存与提示词

应用区分两种缓存：本地结果复用避免再次调用接口，服务端前缀缓存减少一次新请求中的重复输入计费。两者不可混为同一命中率。

服务端命中率按已报告缓存用量的请求计算：缓存输入 Token / 输入 Token，不包含输出 Token。不报告缓存字段的接口显示未知，而不是零命中。不同文章的正文需要重新计算，因此逐篇 RSS 分析的比例通常低于长对话或固定知识库问答。不能通过填充重复文字提高比例来宣称节省费用。

请求依次发送固定分析规则、用户要求、按 ID 排序的分类、获准发送的收藏、相关历史事实、当前文章与可选图片。固定规则不包含时间、文章 ID 或动态统计。收藏和分类变化不会修改固定规则；文章与图片始终位于尾部。缓存是否命中、保留多久以及优惠价格由接口服务商决定；应用不会擅自给兼容接口添加专属缓存参数。

标题按新闻、教程、研究、观点、购物及其他类型生成。购物价格单独显示，保留凑单、会员、数量等条件，不重复到标题中。优惠券门槛、定金、返现及月供不能冒充到手价；无证据不推断历史低价。推荐度以 3 星为中性基线，收藏仅表示兴趣，5 星需要充分依据。

分析规则采用精简提示词，标题通常12至28字，关键规格需要时允许32字，推荐理由最多40字。发送的来源标题最多180字符；正文开头与该标题完全重复且标题不少于12字符时，仅在请求中去掉重复前缀。标题本身仍是有效证据，不能因去重后的正文为空就断言原文缺失。保留其余正文以及用户配置的正文长度上限，不改变原文或图片。输出 Token 上限是保护阈值，不代表实际消耗，因此不会强行降低推理模型的输出上限。

购物标题生成后清理重复售价、折算单价和结尾的“好价”等营销词，保留型号、容量和数量；非购物文章的事件金额不作此清理。明确标注的返超市卡或赠金优惠分别显示实付与返赠权益，不以相减结果代替现金售价。来源没有凑单要求时不会保留模型自行添加的凑单条件。模型价格文本最多保留60字符，减少重要条件被截断的情况。

提示词版本变化会使旧分析结果在下一次主动处理时重新计算。不会批量上传旧文章，也不会修改用户的模型、密钥、个人提示词或分类。强制重新处理会绕过本地结果复用，可能增加调用费用。

## 相关历史复用

AI 设置中的“相关历史与上下文复用”默认关闭，可按需开启；历史预算默认 1600 字符，可在 400—4000 之间调整。这是额外历史输入的字符预算，包含 JSON 与说明，不是 Token 上限，也不占用当前正文的长度预算。

每次从本地仍保留的近 7 天文章中寻找标题关键词相关的旧文，最多检查最近 300 篇获准发送的文章，最多选择 10 篇。未来文章、当前文章和未授权的私有来源不进入历史。标题关键词只是候选筛选，不保证同款商品或同一事件，模型必须重新核对规格、数量、日期与优惠条件，不能据此声称历史最低价。

历史放在固定规则、个人要求、分类和收藏之后，当前文章与图片之前。最近 3 篇保留较长原文片段，较早记录缩短为标题、明确标注价格和短原文证据；超过预算时优先保留较新的记录。保留文章标识和发布时间，不传入旧评级或推荐理由；历史不代表个人偏好。记录会随文章更新、删除、授权和保留期限重新构建，不另存永久记忆。

这里采用可追溯的事实压缩，不调用额外摘要模型，也不递归改写旧摘要，避免摘要费用、通知等待和价格事实漂移。没有相关旧文时不添加历史消息。此功能增加了可用背景，不保证降低每篇费用或提升命中率，应结合实际输入费用与准确性判断。

已缓存的分析是当时的结果快照，不会仅因历史增加就自动重新计费；需要结合最新背景时使用文章的重新处理。历史设置、正文或模型规则改变会在下次处理时更新结果。AI 处理记录显示实际参考篇数和历史字符数，便于核查新增输入。
