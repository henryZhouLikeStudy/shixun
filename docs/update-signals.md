# 更新通知与启动摘要

每次进程启动后，各订阅的第一次成功同步只生成启动摘要，不逐条弹出积压文章。摘要显示未读数量并提供阅读入口；后续新增文章保持单条通知。免打扰期间摘要延后显示。

未读视图在当前停留期间保留已读文章，离开后重新进入才移除。“今天”按本机日期统计文章数量。正文左上角“收起正文”清空详情选择。

AI 设置和订阅编辑中可直接填写 Bearer API Key，留空保留现有凭据。只有自定义请求头、Basic、多参数等高级认证才需要打开高级请求窗口。密钥不会回传到网页或写入日志。

## 更新信号协议

`scripts/push-relay.py` 提供受认证保护的长轮询中转示例。配置 `RELAY_UIDS`（逗号分隔）、`READER_TOKEN`、`RELAY_PUSH_TOKEN` 和可选 `RELAY_DATA`；监听回环地址，由 HTTPS 反向代理提供访问。代理读取超时须大于 45 秒，建议 60 秒。不开放新公网端口。

客户端对 `/rss/weibo/user/{uid}` 来源使用同站点的 `/events/weibo/user/{uid}?since={version}`。首次请求返回版本，随后请求最多等待 45 秒；只有文章内容变化才返回新版本。版本由条目内容的 SHA-256 生成。认证复用该源配置，不向其他站点发送凭据。

Worker 的定时采集推送快照后，中转唤醒等待中的客户端；客户端马上安排读取 RSS。访问者不会触发微博采集。最多同时等待 128 个请求，失败后客户端延迟 10 分钟重试，原有定时同步继续运行。可在“同步与启动”关闭接收服务端更新。

这是应用运行期间的更新信号；电脑关机、程序退出或断网不能接收。它消除客户端定时拉取的一段等待，更新速度仍受上游采集周期约束。其他 RSS 地址继续使用原同步方式。
